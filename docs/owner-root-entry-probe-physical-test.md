# Owner-root XNU visual-entry test — Xiaomi Pad 5 (nabu)

**Date:** 2026-11-06. **Status:** physical EFI handoff requested; screen result **not yet observed**. This is **not an iPadOS installation**.

## Why this test exists

The previous real Pad 5 test displayed the UniXNU menu with a green bar, but the screen remained frozen. UniXNU's debug guide states that green is drawn by DarwinBoot at `DarwinEnter`, blue by the kernel's early entry probe (MMU off), and magenta at the kernel's MMU-on approach. A green-only screen **does not** prove that XNU executed. We needed a stage-by-stage test.

The compiled owner-root kernel has Mach-O `LC_UNIXTHREAD` entry `0xfffffff00b93f488`, shifted **-0x91000** relative to an older probe's static entry. A local read-only preflight decoded its branch target `0xfffffff00b94105c`, uniquely found the expected SCTLR/ISB/CPACR marker `0xfffffff00b941350`, and validated two empty 96-byte code caves. These checks supported instrumenting a **copy** with source-verified relocation, rather than assuming stale addresses.

## What screen outcome will mean

- **Green only:** DarwinBoot reached its kernel-entry handoff; kernel start still unproven.
- **Green + blue:** the instrumented XNU entry code ran with MMU off.
- **Green + blue + magenta:** the kernel progressed near MMU enable. This still does **not** prove the MMU completed, UFS initialized, Apple root mounted or iPadOS userland executed.
- **Black/reset/error:** capture exact on-screen state and return to Fastboot with Power + Volume Down if the tablet gets stuck.

Do **not** erase Android user storage based on this test. The full persistent OS/SystemOS/Data mount still requires separate qualification.
