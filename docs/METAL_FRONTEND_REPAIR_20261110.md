The installed eight-file addon was bound to its build report by every file hash. It uses AdrenoMetal `baad47ca22b181bf0ef0d08412d3ed1f96945e16`, metal2vulkan `624bab3918de5b978e1101517abca2b4fa426565` and the nabu CoreImage experiment, with both `async_fix` and `completion_fix` false. The source records two real frontend defects: five asynchronous creation methods invoke callbacks synchronously, allowing caller-lock reentry, and command-buffer wait methods wait for callback dispatch groups after the actual execution wait, allowing callback-queue/self deadlocks.

This repair builds the four-patch desktop baseline plus both independent frontend corrections. The separate CoreImage and FPS experiments are excluded. `ci/prepare_joint_metal_fix.py` changes only the build helper's combination guard and patch selection, preserving the upstream pinned source and both report flags. The existing async harness exercises the exact five patched methods in 20 bounded baseline/fixed cases. `ci/qualify_metal_completion_wait.py` exercises both exact wait methods in 16 baseline/fixed cases, including pending callbacks, locally failed/uncommitted buffers and a genuinely blocked GPU execution stub. Host results do not qualify hardware rendering.

The registered integrated workflow has an explicit `metal_joint_only` dispatch input that calls the isolated macOS runtime job. It skips the XNU kernel build and USB models. The output is signed open-source userland plus host evidence; there is no device access from CI. Installation is conditional on successful build, qualification, signature-page/CDHash verification and preserved existing trust modules.

A separate observation is that the current run reports one CPU and SMP not requested despite `cpus=8`. The ArmCpu source explicitly gates secondary registration on `sheng-smp`. The existing ADT/topology contract must be checked before enabling this; it is not claimed as the compositor cause or changed by the frontend repair.
